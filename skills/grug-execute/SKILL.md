# Execute a plan (grug way)

1. Read the plan once. If something is wrong or unclear, say so before starting.
2. Track tasks in the todo list; one task in progress at a time.
3. Per task: make the change, run the task's check, read the result. Mark done only when the check passed.
4. Batch: independent reads/greps go in one reply; chain shell steps in one command.
5. Commit after each task or small group if the user wants commits.
6. Stop and ask when: a check fails twice for unclear reasons, the plan conflicts with the code, or a step needs a decision the plan does not make. Do not invent requirements.
7. After every 3-5 tasks give a 2-line status (done, next, any concern).
8. At the end: grug-verify, then grug-finish.
